# Виртуальный процессор и ассемблер

Проект на C/C++: ассемблер, который переводит текстовую программу в байт-код, и виртуальный процессор, исполняющий байт код

## Основные характеристики

- Стековая архитектура (основной стек данных + отдельный стек возвратов для `CALL`/`RET`)
- 4 регистра: `AX`, `BX`, `CX`, `DX`
- Оперативная память (RAM): `[AX]`, `[5]`, `[AX+5]`. Так же является видеопамятью.
- Условные и безусловные переходы, метки, вызов функций
- Простая графика: команда `DRAW` выводит в консоль «экран» из RAM
- Защищенный стэк
- Двухпроходное ассемблирование
- Помимо бинарного файла ассемблер записывает читаемый текстовый листинг

## Структура проекта

| Файл | Назначение |
|------|-----------|
| `processor.h` | Общий заголовок: коды команд, регистры, маски и флаги |
| `assembler/assembler.cpp`, `assembler.h` | Ассемблер: текст → байт-код |
| `executor/executor.cpp`, `executor.h` | Процессор: исполнение байт-кода |
| `stackWithCanary.cpp` | Реализация стека |
| `fileReader.cpp` | Чтение файлов и разбиение на строки |
| `formatingPrint.h` | Цветной вывод (`GREEN_PRINTF`, `ERROR_PRINTF`) |

## Сборка и запуск
Запуск:

```powershell
# Ассемблирование: исходник -> текстовый листинг + бинарный файл
.\assembler\assembler.exe ".\fib.asm" ".\code.txt" ".\code.bin"

# Исполнение
.\executor\executor.exe ".\code.bin"
```

Аргументы ассемблера по порядку:

| № | Аргумент | Описание |
|---|----------|----------|
| 1 | `fib.asm` | Исходная программа на ассемблере |
| 2 | `code.txt` | Текстовый листинг: слова каждой команды в одной строке |
| 3 | `code.bin` | Бинарный байт-код для процессора |

Команды в байткоде:

```
биты 0–4  : код операции (OPCODE_MASK = 0x1F)
бит 5 (32) : FLAG_NUM — есть числовой аргумент
бит 6 (64) : FLAG_REG — есть регистр
бит 7 (128): FLAG_MEM — обращение к памяти (RAM)
```

Далее идут аргументы в фиксированном порядке: **регистр**, затем **число**.

Примеры:

| Ассемблер | Слова |
|-----------|-------|
| `PUSH 5` | `PUSH\|NUM`, `5` |
| `PUSH AX` | `PUSH\|REG`, `0` |
| `PUSH AX+5` | `PUSH\|REG\|NUM`, `0`, `5` |
| `PUSH [AX+5]` | `PUSH\|REG\|NUM\|MEM`, `0`, `5` |
| `JMP :0` | `JMP`, `<адрес слова>` |

## Система команд

| Код | Команда | Описание |
|----:|---------|----------|
| 0 | `HLT` | Остановка программы (выводит стек и сообщение о завершении) |
| 1 | `PUSH arg` | Положить значение на стек |
| 2 | `ADD` | `a = pop; b = pop; push(b + a)` |
| 3 | `SUB` | `a = pop; b = pop; push(b - a)` |
| 4 | `DIV` | `a = pop; b = pop; push(b / a)` (деление на 0 — ошибка) |
| 5 | `OUT` | Вывести вершину стека (без снятия со стека) |
| 6 | `JMP label` | Безусловный переход |
| 7 | `JA label` | Переход, если `top > second` |
| 8 | `JAE label` | Переход, если `top >= second` |
| 9 | `JB label` | Переход, если `top < second` |
| 10 | `JBE label` | Переход, если `top <= second` |
| 11 | `JE label` | Переход, если `top == second` |
| 12 | `POP arg` | Снять значение со стека в регистр или память |
| 13 | `CALL label` | Вызов подпрограммы (адрес возврата — в стек возвратов) |
| 14 | `RET` | Возврат из подпрограммы |
| 15 | `IN` | Ввести число с клавиатуры и положить на стек |
| 16 | `MUL` | `a = pop; b = pop; push(b * a)` |
| 17 | `DRAW` | Нарисовать экран из RAM (`*` — ненулевая ячейка, `.` — нулевая) |

Условные переходы **снимают с стека оба сравниваемых значения**; `top` — значение, лежавшее на вершине, `second` — под ним.

### Аргументы `PUSH`

| Форма | Смысл |
|-------|-------|
| `PUSH 5` | число |
| `PUSH AX` | значение регистра |
| `PUSH AX+5` | регистр + число |
| `PUSH [5]` | ячейка RAM по адресу 5 |
| `PUSH [AX]` | ячейка RAM по адресу из регистра |
| `PUSH [AX+5]` | ячейка RAM по адресу `AX + 5` |

### Аргументы `POP`

| Форма | Смысл |
|-------|-------|
| `POP AX` | снять значение со стека в регистр |
| `POP [5]` | записать в ячейку RAM по адресу 5 |
| `POP [AX]` | записать в ячейку RAM по адресу из регистра |
| `POP [AX+5]` | записать в ячейку RAM по адресу `AX + 5` |


## Синтаксис ассемблера

- Одна команда на строку, имена команд и регистров — **в верхнем регистре**.
- Метка — строка вида `:N`, где `N` от 0 до 9 (всего `LABELS_COUNT = 10` меток). Метка должна стоять **на отдельной строке**.
- Переход на метку: `JMP :N`, `CALL :N`. Также можно указать числовой адрес слова: `JMP 12`.
- Пустые строки пропускаются.
- Ошибки сообщаются с номером строки: неизвестная команда, неверный аргумент, неопределённая метка.

## Пример: факториал

```asm
IN              
POP AX          
PUSH 1
POP BX          

:0
PUSH 1
PUSH AX
JBE :1          

PUSH BX
PUSH AX
MUL
POP BX         

PUSH AX
PUSH 1
SUB
POP AX          
JMP :0

:1
PUSH BX
OUT             
HLT
```
